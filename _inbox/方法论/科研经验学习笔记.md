## 2. 核心经验：按科研生命周期整合

### ① 选题与领域视野（所有来源一致认为：选题 > 能力）

**为什么最重要**
- Hamming：*不做重要问题，就难出重要工作*；私备 10–20 个"重要且有进攻路径"的问题清单，定期回顾，新想法一旦命中就放下一切去追。
- Schulman：*选题品味比技术能力更重要*；动手前问"这是 10% 还是 10× 改进"——增量工作只在服务于大目标时才有意义。
- Nielsen：**难度 ≠ 重要性**；做"问题创造者"而非"问题解决者"；识别"烂摊子"领域（混乱难懂处常藏统一概念）。
- 周志华："问题"是科研的心脏，*提出好问题已成功一半*；**宜"小题大做"，忌"大题小做"**。
- 彭思达：选题决定论文的 **Novelty 和价值**；用"4 种情况"判断创新空间（同任务小改进 → 跨域同类技术有解 → 少数域有解 → 各域都无好解，越靠后创新空间越大）。

**怎么建立领域视野（彭思达 slides 的精华）**
- 领域视野 = 知道有哪些 **milestone papers**、技术如何随时间演变、终极目标是什么、已达什么水平、还有哪些未解重要问题、当前热点。
- 方法：确定 milestone papers → 向前（它引用谁）向后（谁引用它，工具 Connected Papers）找论文 → 读 → 整理成**时间轴思维导图**，区分 milestone vs follow-up → 总结技术范式与热点问题演变。
- 识别 milestone：找该领域被引最多的论文按日期排序 + 问资深研究者。
- 视野大小要**匹配个人能力**：初学者 narrow，强者越看越宽。

**选题陷阱（彭思达）**
1. 倾向做"有明显答案"的题 → 收获阅读量近 0 的论文。
2. 知道有哪些题但忘记按重要程度排序，能做就动手。
3. 选了对终局重要但"今年不该做"的题（技术就绪度不够 / 个人能力不足）——"想做分子料理牛排，但连饭都不会做"。
- 口诀：**Aim high**——选个人能力范围内最重要的课题；技术风险高的课题往往收益更高。

**Goal-driven vs Idea-driven（彭思达 + Schulman 共识）**
- Idea-driven（看到一篇 SOTA → 找它的 failure case → 改）：易上手，但易被带偏、易撞 idea、影响力有限、创新空间窄。
- Goal-driven（设定想实现的终极能力 → 规划 roadmap → 选当前最有价值任务 → 解决本质技术问题）：易出突破性创新、有 motivation、成体系、吸引他人；难点是规划好 roadmap 很难。
- 彭思达的 roadmap 制定：用 **literature tree**（列出方向论文 → 按 milestone task 归类 → 每个 task 梳理代表性 pipeline）判断哪些任务重要、研究空间大。
- Schulman 补充：goal-driven 要避免"太字面"，约束自己找通用、可迁移的解。

### ② 想 Idea / 方法设计

**第一性原理（彭思达反复强调）**
- 设计方法四步：**分析原因（为什么 SOTA 不够好）→ 设计方法 → 判断合理性 → 改进**。
- 一个事实：*所有方法都是在创新地组合已有技术*——ResNet = CNN + Skip Connection；NeRF = Neural Field + Radiance Field；DreamFusion = ClipNeRF + SDS Loss。
- 理想方法 = **用新技术解决问题**（新技术 + 有效性强相关；改进现有技术通常无大突破，否则早被别人发现）。
- 5 级技术创新：①崭新范式 ②新颖模块 ③重组已有模块成新 pipeline ④加简单改进模块 ⑤加现有模块——越靠前影响力越大。

**武器库 / challenge-insight tree（彭思达独有）**
- 很多任务存在相似的 technical challenge，解决它们的技术是通用的 → 积累"武器库"。
- 用 **challenge-insight tree** 整理：该方向有哪些 technical challenges、有哪些 techniques/insights 在解它们。
- 想 idea 的循环：发现 failure cases → 分析其**本质技术原因**（抽离表面问题）→ 从武器库选技术解决。
- 关键判断：**重要 failure cases 的解法一定是 novel 的**（若简单组合可解，说明该 failure case 不重要）。

**Freeman 的辅助思维**
- **epsilon 邻域法则**：方案失败时不要直接汇报失败，在原方案附近搜索变体找到能 work 的再汇报。
- **TSTMTCTCI**（The Simplest Toy Model That Captures The Main Idea）：用最简玩具模型抓住主要思想，建立直觉、提前判断可行性。
- 一次只改一个变量，才知道实验结果意味着什么。

**周志华的 idea 自检**：是新 idea 吗？有道理吗（非瞎蒙）？可行吗？放到一边过一周再看是否有更好办法——都 yes 就动手。

**特殊机会**：新锤子出现时，拿它做 roadmap 上的某个 milestone task 容易出有影响力工作（NeRF → VolSDF/NeuS；Stable Diffusion → DreamFusion）。

### ③ 做实验与迭代（彭思达的核心模型）

**SGD 优化 Idea 模型（彭思达反复用的比喻）**
- 把做实验视作基于 SGD 优化 Idea：目标函数 = ||Experiment(Idea) − Target result||；**实验反馈 = 梯度**。
- 核心步骤是**分析实验不 work 的原因**——无根据地改 idea = 随机梯度，收敛慢；分析原因 = 正确梯度。
- 循环速度决定 project 时间：1 天 5 次循环 vs 1 天 1 次，前者 1 个月 = 后者 5 个月；慢还会被 scoop。

**7 步改进法（GAMES003 w5）**
1. 从文献学习（找相关技术论文的 3 目的：检查 novelty / 获得 insights / 学关键 tricks；用 challenge-insight tree 总结）
2. 向其他 researchers 学习（讨论三好处：组织思路 / 获反馈 / 激发新 variants）
3. 提出 **idea variants（越多越好）**——避免 local minima、培养创造力；误区是直接用导师 coarse pipeline 跑实验而不深思
4. idea 实现（在优秀代码框架上实现；更好是**在自己框架内重构他人代码**——省时、学 tricks、便于后续改进）
5. 设计实验（核心原则：**减少探索点数量**；分解 pipeline + 分解实验设置，从简单 setting 渐进；按重要性排序）
6. 分析实验结果（保持实验记录 5 要点：目的/设置/结果/分析/下一步）
7. 改进 idea（三件事：**不轻易放弃** / **不断质疑是否有根本缺陷** / **知道何时可放弃**）

**实验不 work 的诊断流程（彭思达 + Freeman 共识）**
- 表层原因 → 本质技术原因 → 实验验证。
- **二分查找**：找到 work 的数据/算法，与不 work 的对比，看差异（Freeman 的"一次改一个变量"同源）。
- 本质原因通常两类：①代码有 bug ②算法在该数据上确实有问题（超参没对 / 缺 tricks / 算法本身不行）。
- 调算法：看相关论文**为什么能 work**、用了什么 tricks；给相关算法做 ablation 看哪部分关键——"有些 idea 单独不 work，要加 tricks 才 work（如 NeRF + positional encoding）"。
- 调代码：彻底理解算法 → 确定能稳定复现的输入 → 二分缩小范围 → 逐行调试 + 控制变量。
- 可视化工具调试：Viser / Wis3D；观察 failure cases 是否有特定 pattern。

**简单实验先行**：只存在 core technical challenge 的实验先做——成本低、无其他 challenge 干扰、能确定解法是否 work。

**Freeman 的诊断式汇报**：报告"不 work"时说明在哪一步失败（到 A 步正常、B 步失败）、给输入输出证据、列出已排除的原因——不要只说"它不 work"。

**Schulman 的记录习惯**：每日研究笔记本（想法/实验/图表），每 1–2 周回顾凝练成"发现/洞见/代码进展/下一步"，并回看上周是否落实；价值在捕捉转瞬想法、统一存放结果、监控时间去向。

### ④ 写论文

**周志华：论文是"做"出来的不是"写"出来的**
- "写"的时间最多占 10%；没有研究支撑，论文难写。
- 论文要说清的正是：Problem X 重要 → A/B/C 已做但有弱点 → 我们 D → 理论分析 + 实验对比 → 为何 D 更好 → D 的 strength/weakness → future works。
- 结构：Title / Abstract / Introduction / Previous works / Your contribution / Support（理论或实验）/ Discussion / Conclusion / Reference。
- **4 个误区**：①越多越好（应聚焦核心）②越复杂越好（要易懂，数学是帮表达不是显深度）③越卖越好（别夸大）④越权威越好（别只引自己、别装大佬）。
- 技巧：读得多写得多、用好论文当样本（仿不抄）、用简单句、缩写要易发音（STARE > SBRE）、按目标排版、**反复改**（每次搁置一段时间、请别人读）、从评论中改进。

**彭思达：写作 9 步规划 + 故事 + self-review**
- 9 步：①画 pipeline figure 草图 + 梳理 story + 写 intro 初稿 → ②列 comparison/ablation 并开始做 → ③写 method 同时做实验 → ④改 intro/method 同时做实验 → ⑤实验差不多了写 experiment → ⑥写 related work → ⑦Review 改 intro/method/experiment → ⑧写 abstract + 取名 → ⑨反复 review 改。
- 规划目的：避免最后熬夜、大幅提高投稿率。
- **故事梳理**：先用"输入→模块1→中间输出1→…→输出"文字描述 pipeline 并画草图；再按序回答 4 问（贡献是什么 / 贡献解决了哪些 challenge / 带来什么新 insights / 如何由以往方法引出我们的 challenge 与 insights）；最后概述故事。
- **写 method**：每个 subsection 三部分——模块具体设计（给定 xxx 输入，第一步…最终得 xxx 输出）+ motivation + 技术优势。
- **self-review checklist（5 大类拒稿因素）**：
  1. 技术贡献不够（failure case 很常见 / 技术 well-explored、提升可预见）
  2. 写作不清楚（intro 没说清贡献 / pipeline figure 不清 / 缺技术细节不可复现 / 模块缺 motivation）
  3. 实验效果不够好（只比之前好一点 / 虽好但仍不够）
  4. 测试不充分（缺 ablation / 缺重要 baseline 或 metric / 数据太简单）
  5. 方法设计有问题（setting 不实际 / 技术缺陷 / 不鲁棒需每场景调参 / 新方法 benefit 被更强 limitation 抵消）

**Hamming：必须"推销"**——*It is not sufficient to do a job, you have to sell it.* 学会清晰写作、正式演讲、非正式发言；≥50% 时间用在表达与打磨；让人愿意放下手头事来读你。

**彭思达画图**：pipeline 图 / teaser 图 / 定量结果 / 定性结果；好图 = 好线条+框图+元素可视化+配色，目的是提高中稿率。

## 3. 心态与成长（最被低估的部分）

**彭思达《CCF优博》的五阶段认知（个人复盘，极有启发）**
1. **入门**：反馈周期从本科的"几周出分"变科研的"半年无结果" → 解药是**"微快乐"思维**——搞懂一个符号、复现一小段代码、用自己的话讲清思想都快乐；从过程而非结果寻求正反馈。
2. **第一篇论文**：怕失败的精神内耗 → 解药是**《实践论》**——实践→认识→再实践→再认识，螺旋上升；**失败的实验 = 认知提升**（排除了一个错误路径），不是浪费时间。
3. **持续深耕**：避免"学术游击队"（打一枪换一个地方）→ **"根据地"思维**，建立科研根据地；"你打你的，我打我的"，掌握主动权。
4. **实际意义**：空虚感 → **从行业中来，到行业中去**；研究问题源于真实应用场景与工业界痛点；Goal-driven + Problem-driven。
5. **教育传承**：写文档不够（"只见树木不见森林"，文字线性难呈全景）→ **画图思考法**：思考草图（非精美展示图）强迫模糊思维清晰化、建立结构化逻辑；三类图——自顶向下思考流程图 / 领域技术布局图 / 技术范式图；借此养成**系统思维**。

**Hamming**
- *Knowledge and productivity are like compound interest*——多 10% 努力一生产出多一倍以上；但 misapplied effort 无效，努力要明智施加。
- 勇气：敢于追独立想法、问不可能的问题；*If you think you can't, you almost surely are not going to.*
- **容忍模糊**：信理论到足以前进，疑它到足以发现错误（达尔文专记相悖证据）。
- **喂饱潜意识**：深度沉浸，潜意识日夜琢磨，答案清晨浮现。
- **开门 vs 关门**：关门今天效率高，但十年后可能在"稍微错误的事"上努力；开门有打扰，但能得到关于重要性的线索——开门者更易做重要工作。
- 早年成名会"绝育"（Brattain、Shannon 之后难做小事）；别停止种小橡子。
- 别用"我想到过但没做"找借口：*Why weren't you first?*

**Freeman**：到了研究生阶段周围人都聪明，*it's the hard workers who pull ahead*；做你热爱的事（热爱→愿投入→变强）；既要有"马达"（努力）也要有"舵"（定期确认在做对的事）；广义理解"进展"（证明为什么不行、把任务简化到能跑、整天读文献都是进展）；不要躲着导师。

**Nielsen**
- *We are what we repeatedly do. Excellence is not an act but a habit.*——研究效能 = 建立正确习惯。
- 主动性：你是自己研究效能的最终责任人；警惕三种推卸责任（怪外部 / 做替代性琐事 / 自我消耗式低落）。
- **秒表自测**：连续一周用秒表记每天真实研究时长（有人一天仅 0.5 小时），建立诚实认知，再设简单、可周评的书面行为目标。
- **Kolmogorov 技巧**：把大问题放进更大事业（开研讨班/写讲义/出书），保证无论如何都有产出、降低心理压力。
- **Feynman 技巧**：骗自己"我对这问题有独特内线"以建立前进势头。
- **独特能力组合（比较优势）**：*anybody can be better than everybody some of the time*——跨界 X+Y 且深学对方领域的人极少，少数做了的成果惊人。
- 平衡自我发展与创造性研究：只顾自我发展会早退场，只顾发论文会停滞。

**Schulman**：持续个人成长——拨时间学通用 ML 知识（不止当前项目）否则知识停滞；早期职业教科书与论文时间各半（教科书/博士论文信息密度高、有序、统一记号）；**亲手重实现最喜欢的经典论文**（理解更深、获实验经验、反馈快，目标性能已知），能复现 SOTA 才具备超越它的资格。

**李武军（本科生科研）**
- 适合科研的本科生：①对科研感兴趣（能静心连续十几小时读文献/思考/观察实验）②勤奋踏实（不找理由搪塞）③扎实基础（成绩优秀且学有余力）。
- 时间点：大二暑假开始到毕业；大四毕设开始太晚。
- 原则：只进一个组、坚持到毕业、与研究生完全同样的管理制度。
- 培养目标以兴趣为主，重点在"算法+实验"，弱化"问题"阶段；多数本科生完成一个题/一篇论文即达目标，独立科研能力留到博士。

## 4. 环境与合作

- **Hamming**：找**临界质量**而非吸音体——能反过来激发你的能人对谈，不是只会说"是"的人。
- **Schulman**：最有影响力的工作高度集中在少数研究组——是"专长与视角密度"使然而非人更聪明；加入同领域研究组。
- **Freeman**：经营你的"品牌"（总是做出好工作、有好想法、报告精彩的声誉）；培养并发挥长处；不要对相关文献一无所知。
- **Nielsen**：人们低估环境作用；任何人都能发起研讨会/读书会/休息区；机构记忆长，改善会留存并放大杠杆；通过带学生、合作、导师关系获得**问责**。
- **彭思达**：导师与学生**互相促进**，警惕某一方单向输出——学生要给有效反馈（相关论文、对任务/问题的想法、解法设计与改进、实验现象分析、不 work 原因、下一步）；学生无反馈则导师长期不知如何建议。讨论要讲清五要点：实验目的/设置/现象/猜测的原因/能确定的范围。
- **李武军**：导师给本科生的题必须明确具体、自己已有初步思路；把第一个题限定在 3–6 篇参考文献（1–2 篇需改进的方法即思路来源 / 1–2 篇算法设计参考 / 1–2 篇实验评测参考）。

## 5. 跨来源共识与个性

**5 条最强共识**
1. **选题优先于能力**：Hamming/Schulman/Nielsen/周志华/彭思达全部强调——定期退一步想"什么重要"。
2. **聪明地努力 + 长期复利**：过了智力门槛后，drive 与一致性决定高下；但方向必须对（Hamming 的 misapplied effort、Freeman 的"一次只改一个变量"）。
3. **深度沉浸喂饱直觉/潜意识**：Hamming 的潜意识、Freeman 的玩具模型、Nielsen 的多表述、彭思达的 SGD 梯度——换表述/换模型/换视角比硬刚有效。
4. **不要闭门造车**：进好环境、找对人、学会写作与推销——Hamming/Schulman/Freeman/Nielsen/彭思达一致。
5. **持续自我发展 + 诚实自评**：Nielsen 的秒表、Schulman 的重实现、Hamming 的"为何你不是第一"、彭思达的 self-review checklist。

**几处"个性/可争论"之处（保持批判）**
- 彭思达强调 **goal-driven > idea-driven**，但 Schulman 也提醒 goal-driven 易"太字面"；周志华的 TPIC 更接近 problem-driven。三者并非矛盾，但"终极目标多远"因人/阶段而异。
- Hamming 主张**每 7 年换领域**保持新鲜，而彭思达主张**根据地思维**深耕一个方向——这是"广度换新"vs"深度成专家"的经典张力，看你处于哪阶段。
- 周志华说"写只占 10%"，Hamming 说"≥50% 时间表达打磨"——不矛盾：前者指研究是根基，后者指交付同样决定成败。

## 6. 可立刻执行的行动清单

- [ ] 每周固定 **"Great Thoughts"时间**（~10%）：只问"什么重要、领域往哪走"，发现走错就改方向（Hamming）。
- [ ] 维护 **10–20 个重要问题清单**，定期回顾；新想法命中其一就追（Hamming）。
- [ ] 给自己的方向建一张**时间轴思维导图**（milestone vs follow-up + 热点问题演变），判断哪些任务重要、空间大（彭思达）。
- [ ] 建 **challenge-insight tree**（武器库）：方向有哪些 technical challenges、哪些技术可解（彭思达）。
- [ ] **每日研究笔记本** + 每周末凝练"发现/洞见/代码进展/下一步"，回看上周是否落实（Schulman）。
- [ ] 用**秒表**连续一周测真实研究时长，设简单可周评的书面目标（Nielsen）。
- [ ] 做实验严格**一次只改一个变量**；不 work 时按"表层→本质→验证"诊断，用二分查找定位模块（Freeman + 彭思达）。
- [ ] 报告失败用**诊断式协议**（哪步失败、输入输出证据、已排除原因），并在 epsilon 邻域找变体后再汇报（Freeman）。
- [ ] 写论文先**画 pipeline 草图 + 写 intro 初稿**，再列 comparison/ablation；按 9 步规划推进（彭思达）。
- [ ] 投稿前用 **self-review checklist**（5 大类）自查一遍（彭思达）。
- [ ] 降低正反馈阈值，培养**微快乐**；把失败实验记为"排除一条错误路径"的认知收益（彭思达）。
- [ ] 每周拿**一天**做完全不同的事（epsilon-greedy），防止陷入局部最优（Schulman）。

## 附录 A：Challenge-Insight Tree 模板（彭思达）

> 用途：积累"武器库"，把方向的 technical challenges 与可解它们的技术关联起来，便于想 idea。

```
研究方向：<你的方向>

├─ Challenge 1：<本质技术挑战，如"稀疏视角下观测不足导致优化陷局部最小">
│   ├─ Insight/Technique a：<来源论文> 的做法 + 其技术优势
│   ├─ Insight/Technique b：……
│   └─ Insight/Technique c：……
│
├─ Challenge 2：<……>
│   └─ ……
│
└─ Challenge 3：<……>
    └─ ……

待用新技术（新锤子）：
- <技术名>：可能解 Challenge __，尚未在本领域被 well-explored
```

**使用方式**：发现 failure case → 分析其本质技术原因 → 在树中找匹配 challenge → 选一个未 well-explored 的技术来解 → 设计 pipeline。

## 附录 B：实验不 work 诊断清单（彭思达 + Freeman）

```
1. 确认表层原因（哪个模块/数据/参数导致了不 work）
   □ 找到 work 的数据/算法，与不 work 的对比，看差异（二分查找）
   □ 可视化各模块中间输出是否满足预期（Viser / Wis3D）
   □ 观察 failure cases 是否有特定 pattern

2. 确定本质技术原因（列尽量多的候选，问"为什么"）
   □ 代码有 bug？
       - 彻底理解算法/代码
       - 确定能稳定复现的输入
       - 二分缩小范围 → 逐行调试 + 控制变量
   □ 算法在该数据上确实有问题？
       - 超参没设对？
       - 缺 tricks？（看相关论文为什么 work、做 ablation）
       - 算法本身确实不行？

3. 通过实验验证找到的原因
   □ 先确定真是"技术原因"再改算法

4. 改进 idea（三件事）
   □ 不轻易放弃当前 idea（第一次不 work 不代表不可行）
   □ 不断质疑是否有根本缺陷
   □ 知道何时可放弃（发现根本缺陷 / 资源不足）
```

| 项目 | 内容 |
|---|---|
| 实验目的 | 为什么做这个实验，希望从中获得什么 |

## 附录 D：论文写作 9 步规划（彭思达）

```
Step 1  画 pipeline figure 草图 + 梳理 story + 写 intro 初稿
Step 2  列 comparison experiments + ablation studies，并开始做
Step 3  写 method（同时做实验）
Step 4  改 intro 和 method（同时做实验）
Step 5  实验差不多后，写 experiment
Step 6  写 related work
Step 7  Review 论文：改 intro / method / experiment
Step 8  写 abstract，取论文名字
Step 9  反复 review，改论文
```

**故事梳理 4 问**：
1. 我们的 pipeline 有哪些贡献（新任务 / 新技术挑战 / 新技术贡献）？
2. 贡献有哪些好处？解决了哪些技术挑战？
3. 论文带来哪些新 insights？
4. 如何通过介绍以往方法引出我们关注的技术挑战与新 insights？

**写 method 每个 subsection 三部分**：模块具体设计（给定 xxx 输入，第一步…最终得 xxx 输出）+ motivation + 技术优势。

## 附录 E：投稿前 Self-Review Checklist（彭思达）

```
1. 技术贡献是否足够
   □ 想解决的 failure cases 是否很常见（常见=贡献低）
   □ 提出的技术是否已被 well-explored（提升是否可预见/well-known）

2. 论文写作是否清楚
   □ Introduction 是否清楚描述贡献
   □ pipeline figure 是否清楚描述 pipeline 与技术贡献
   □ 是否缺技术细节导致不可复现
   □ 每个方法模块是否都写了 motivation

3. 实验效果是否足够好
   □ 是否比之前方法好很多
   □ 效果是否让人 impressive

4. 实验测试是否充分
   □ 是否缺 ablation studies
   □ 是否缺重要 baselines / 重要 evaluation metric
   □ 数据是否太简单（无法证明方法真的 work）

5. 方法设计是否合理
   □ 实验 setting 是否实际
   □ 方法是否存在技术缺陷（看起来不合理）
   □ 方法是否鲁棒（是否需在每个场景调超参）
   □ 新方法是否 benefit 被更强 limitation 抵消（收益为负）
```
